# Avi CMS

A headless-first content management system built with [Avi.js](https://github.com/chrischase011/avi-js)
for the API and React for the admin interface.

- **Backend:** Avi.js 1.1 (modules, decorators, generated dependency lists), PostgreSQL, Drizzle ORM, Zod
- **Admin UI (`web/`):** React, TypeScript, Vite, React Router, Tailwind CSS, shadcn/ui, TanStack Query, React Hook Form, Tiptap
- **Auth:** JWT in an HTTP-only cookie, double-submit CSRF token, scrypt password hashing, roles

The API is documented in [docs/API.md](docs/API.md).

## Quick start

Requirements: Node.js 22.12+ and PostgreSQL.

```sh
npm run install:all          # root and web/ dependencies
cp .env.example .env         # then set DATABASE_URL, JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
npm run db:migrate           # create the tables
npm run db:seed              # first administrator + sample content
npm run dev                  # API on http://localhost:3000, admin UI on http://localhost:3001
```

`./run.sh` does the same as `npm run dev` and clears Vite's cache first.

Sign in at http://localhost:3001 with `ADMIN_EMAIL` / `ADMIN_PASSWORD`, then remove
`ADMIN_PASSWORD` from `.env`.

## Scripts

| Command                | Does                                                                      |
| ---------------------- | ------------------------------------------------------------------------- |
| `npm run dev`          | API (`avi dev`, restarts on change) and admin UI (Vite) together          |
| `npm run dev:api`      | API only                                                                  |
| `npm run dev:web`      | Admin UI only; proxies `/api` and `/uploads` to the API                   |
| `npm run build`        | `avi build` for the API, then the admin UI into `web/dist`                |
| `npm start`            | Run the built API (serves `web/dist` too when `SERVE_WEB=true`)           |
| `npm run typecheck`    | Type-check the API and the admin UI                                       |
| `npm test`             | API tests against `TEST_DATABASE_URL` (wiped on every run)                |
| `npm run check`        | `avi check`: verify hand-written `static inject` lists                    |
| `npm run db:generate`  | New migration in `drizzle/` from `src/database/schema.ts`                 |
| `npm run db:migrate`   | Apply pending migrations                                                  |
| `npm run db:seed`      | Create the administrator and, on an empty database, sample content        |
| `npm run setup:admin`  | Create the administrator only                                             |
| `npm run db:studio`    | Drizzle Studio                                                            |

## First administrator

Credentials are never in code. `npm run setup:admin` (or `db:seed`) reads `ADMIN_EMAIL`,
`ADMIN_PASSWORD` (10+ characters) and `ADMIN_NAME` from the environment or `.env`, and creates the
account only if no user with that email exists. Running it again changes nothing.

## Roles

| Role   | Can                                                                                       |
| ------ | ----------------------------------------------------------------------------------------- |
| Admin  | Everything, including users and settings                                                  |
| Editor | All posts and pages, publishing, categories, tags, all media                              |
| Author | Own posts only, as drafts (an editor publishes them); upload media, delete own uploads    |

Accounts are deactivated rather than deleted, so content keeps its author.

## Security

- Passwords: scrypt (`node:crypto`), timing-safe compare, the same answer for unknown emails.
- Sessions: HS256 JWT in an `HttpOnly`, `SameSite=Lax` cookie (`Secure` with `COOKIE_SECURE=true`).
  Each token carries the user's token version; deactivating a user or changing a password ends
  their sessions at once. Every request re-checks that the account is active.
- CSRF: state-changing `/api` requests must echo the `avi_cms_csrf` cookie in `x-csrf-token`.
- Login is rate limited per client (`AUTH_RATE_LIMIT` per 15 minutes) with `@avijs/security`.
- Security headers on every response; CORS with credentials only for `WEB_ORIGINS`, `*` without
  credentials for `/api/public/*`.
- Validation on every route with Zod (Standard Schema); response schemas on user and public
  routes drop any field not listed, so hashes and private fields cannot leak.
- Rich text is sanitized on save with `sanitize-html`, and again with DOMPurify before preview.
- Uploads: PNG, JPEG, GIF and WebP only (no SVG), checked by their bytes, size-limited,
  stored under random names, served with `nosniff` and a sandboxing CSP.
- Constraint violations (duplicate slug or email) become `409`, bad references `400`; 5xx
  details never reach the client.

## Production

```sh
npm run build
NODE_ENV=production SERVE_WEB=true COOKIE_SECURE=true npm start
```

With `SERVE_WEB=true` the API serves the admin UI and falls back to `index.html`, so a refresh
on `/posts/12/edit` works. Behind a proxy, set `TRUST_PROXY`. Logs are JSON lines (`jsonLogger`).

To store media in S3-compatible storage, implement the three-method `FileStorage` interface in
`src/modules/media/storage.ts` and swap the factory in `media.module.ts`.

## Avi.js notes

What this project uses from Avi.js: `avi new` (modular, Zod), `avi g resource/module/service/controller`,
decorators with constructor-inferred dependency lists (`inject.gen.ts`), `defineConfig`,
`defineFactory` with `dispose`, guard classes with DI, `ctx.need()`, route and response schemas,
`@avijs/security` (headers, CORS, rate limit guard), `@avijs/multipart` (`readForm` with
`accept` and limits), `@avijs/testing` (`createTestClient` with `overrides`), `jsonLogger` /
`logRequests`, and `onRequest` hooks.

Limitations found:

- **No cookie helpers.** Avi.js has no API for reading or setting cookies, so `src/common/cookies.ts`
  parses `Cookie` and writes `Set-Cookie` itself.
- **No built-in CSRF protection.** Implemented as an `onRequest` hook (`src/common/csrf.ts`).
- **No static file serving.** `/uploads` and the built admin UI are served by small controllers.
- **Module `prefix` applies only to a module's own controllers**, not to imported modules, so each
  feature module sets `prefix: '/api'`.
- **CLI:** `avi g controller public` generates `constructor(private readonly public: PublicService)`,
  which does not compile (`public` is a reserved word). Renamed by hand.
- **CLI:** `avi generate` treats a `src/app.ts` as the minimal-template marker, so app options live
  in `src/app.options.ts`.
